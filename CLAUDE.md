# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

A single-page personal portfolio/CV site for Ian Jordy Lopez Diaz (Data
Scientist, Physics Ph.D.), built with [Quarto](https://quarto.org/) and
published to GitHub Pages via the `gh-pages` branch. There are no notebooks
in this project - all content lives in `index.qmd`.

## Structure

- `index.qmd` - the entire site content (profile header, summary, skills,
  experience, education, projects, publications), organized as collapsible
  `.callout` sections.
- `_quarto.yml` - site config: title, theme (`minty` light / `solar` dark,
  toggleable), footer.
- `styles.css` - custom CSS for the profile header/photo/social links.
- `assets/img/` - `headshot_circle.png` (the only image `index.qmd`
  references), `input.png` (source photo), and `crop.sh` (regenerates
  `headshot_circle.png` from `input.png` via ImageMagick). Older working
  variants were moved out to the root-level `assets/` folder, outside this
  git repo.
- `assets/curriculum/` - LaTeX CV sources (`ian-curriculum-en.tex`,
  `ian-curriculum-pt.tex`) and their built PDFs, which `index.qmd` links to
  directly. `make.py` builds the PDFs from the `.tex` sources.
- `scripts/publish.sh` - renders and publishes the site to `gh-pages`.
- `_site/` - Quarto's rendered output. **Not tracked in git** - it's
  regenerated by `quarto render`/`quarto publish` and pushed straight to the
  `gh-pages` branch, never committed to `master`.
- `environment.yml` / `requirements.txt` - intentionally near-empty; the
  site needs no third-party Python packages (see Working conventions).

## Common commands

```bash
quarto preview          # live preview while editing
quarto render            # render _site/ locally without publishing
./scripts/publish.sh     # render + publish to gh-pages (non-interactive)
```

First-time publish on a fresh clone: run `quarto publish gh-pages`
interactively (no `--no-prompt`) once, so Quarto can create `_publish.yml`
and record `gh-pages` as the destination. After that, `scripts/publish.sh`
works non-interactively.

## Working conventions

- This is a content site, not an application - most changes are edits to
  `index.qmd` (profile text) or `styles.css` (layout/appearance). There's no
  build step, test suite, or linter to run.
- Don't commit `_site/` - it's git-ignored on purpose (see
  `quarto-untrack-publish.md` in the parent `ian-portfolio/` folder for the
  rationale, which was applied here on 2026-07-18).
- Keep `assets/img/` limited to images actually referenced from `index.qmd`;
  avoid re-adding large intermediate/working images to version control.
- This project has no real Python dependencies - `index.qmd` has no code
  cells and `assets/curriculum/make.py` only uses the standard library.
  `environment.yml`/`requirements.txt` reflect that on purpose; don't add
  packages to them unless the repo actually starts using them (e.g. a
  Jupyter-engine code cell gets added to `index.qmd`).
- Never publish (`quarto publish` / `scripts/publish.sh`) or push to
  `master`/`gh-pages` without the user's explicit go-ahead for that specific
  change.
